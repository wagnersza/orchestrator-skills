1. The idea in one minute

You keep a list of issues in your tracker, such as GitHub Issues. Some of them are small, clear tasks an AI agent could do on its own. The orchestrator lets you hand those tasks off.

You mark an issue as ready and assign it to yourself. A minute later an agent starts working on it, in its own private copy of the repo, so it never gets in anyone's way. When it finishes, it opens a pull request. You review the PR like you would review a colleague's, and you say when to merge.

Think of it like a small team. You are the lead who decides what gets done and approves the result. The agents are helpers who each take one task. A clock on the wall checks on everyone once a minute. The tracker is the shared whiteboard where everyone can see who is doing what.

⏳

Waiting is free

The once-a-minute check is a plain script, not an AI. Nothing is spent while the helpers work.

💬

Your chat stays yours

"work on 42" answers right away. Keep talking about anything else while up to three helpers work in parallel.

✅

You stay in charge

You decide what is ready, you review every PR, and nothing merges until you say so.

2. Who does what

🧑‍💻

You

Pick which issues are ready, review the pull requests, answer questions, say "merge".

🎛️

The orchestrator

Your Claude Code chat. It understands a few short requests, such as "work on 42" or "status". It never writes code itself.

🤖

A worker

One AI agent on one issue, in its own copy of the repo. It writes the code and tests, and opens the PR.

⏱️

The tick

A tiny check that runs every minute. It sees who finished, updates the labels and starts the next issue when a slot frees up.

📋

The tracker

GitHub, GitLab or plain markdown files. Every issue's status lives here as a label, and nowhere else.

🐋

Orca

The desktop app the workers run in. It holds each worker's terminal and copy of the repo, so you can watch any of them.

3. The journey of one issue

Every issue the orchestrator handles wears exactly one of four labels. The label is the whole story: look at it, and you know where the issue stands.

→
The tickClaims itWithin a minute it swaps the label to in-progress and starts a worker.
→
The workerDoes the workWrites code and tests, reviews its own change, opens a PR.
→
The tickHands it to youThe label becomes ready-for-human.
→
YouReview and mergeSay "merge 42". The worker's copy is cleaned up and the issue closes.
LabelWhat it meansWhat moves it on
ready-for-agentReady to start. "work on N", or the tick once the issue is assigned to you.
in-progressA worker is on it. The worker reports that it is done or stuck.
ready-for-humanA PR is waiting for your review.You merge it, by saying "merge N" or on the tracker.

The only label you ever set yourself is ready-for-agent. The orchestrator moves all the others, so the labels always tell the truth.

When a worker starts, Orca also opens the issue's page in a browser tab next to it, so the issue's comments sit right beside the work.

4. What you say to it

You talk to your Claude Code chat in plain words. It knows four requests:

You sayWhat happens
"work on 42"Starts a worker on issue 42 right now, even if it is not assigned to you.
"status"Shows what is running, what is next in line, and why anything else is waiting.
"merge 42"Merges the PR of issue 42, cleans up and closes the issue.
"set up the orchestrator"Runs the setup again, to change anything.

Or say nothing at all. Assign a ready issue to yourself, and the tick picks it up within a minute. Issues nobody has assigned to you just wait, so nothing starts behind your back.

5. When a worker gets stuck

Sometimes a task is unclear, or a test will not pass. A worker in that spot does not keep guessing. It stops, and the issue turns needs-human with a comment in the worker's own words, such as a question it needs answered.

  1. Read the comment on the issue.
  2. Reply with your answer, right there on the issue.
  3. Set the label back to ready-for-agent.
  4. A fresh worker starts in the same copy of the repo, reads your reply first and picks up where the last one stopped.

Nothing is lost if something crashes. Since all the status lives in the tracker's labels, the next tick simply looks at the labels and carries on.

6. The right model for each job

A one-line fix should not need your most expensive AI model. Each issue runs in one of three roles, and each role has its own agent, model and effort level:

🏋️

Heavy

Big or tricky work. Picked by the heavy label, or when the issue lists three or more files it will touch.

⚖️

Medium

The everyday default for any issue that is not heavy or light.

🪶

Light

Small, simple work. Picked by the light label.

The pick follows fixed rules, so it costs nothing and you can always predict it. You can also say "work on 42 as heavy" to choose for yourself.

Workers can run on any of five agent tools: claude, codex, cursor, pi and copilot. You can mix them, for example Claude Opus for heavy work and Codex for light work.

7. Bigger work: a whole story

A big feature is often split into a parent issue (a "story") with smaller child issues under it. Some children may depend on others.

  • Mark each child ready-for-agent, and assign the parent to yourself.
  • Each child starts as soon as nothing it depends on is still open, so the story runs in the right order by itself.
  • When the last child is closed, the tick closes the parent too.

8. Setting it up

What you need

  • Claude Code, for your orchestrator chat.
  • The Orca app, where the workers run.
  • Node 22.18 or later.
  • The GitHub CLI (gh) for GitHub, or glab for GitLab. A markdown-file tracker needs neither.

Don't worry about installing all of these by hand: setup checks each one and installs what it can.

Install the plugin, once

In your terminal:

claude plugin marketplace add wagnersza/orchestrator-skills
claude plugin install orchestrator-skills@wsza

Set up each repo, once

  1. Open the repo in Orca and start Claude Code in an Orca terminal. Setup has to run there, because it registers the repo with Orca.
  2. Say "set up the orchestrator." It asks you a few questions, one at a time, and always suggests an answer, so you can just accept:
    • Which tracker? It reads this from your repo's docs, so usually it does not even ask.
    • Which cost profile? This fills in all three roles at once:
      ProfileHeavyMediumLight
      Balanced (suggested)Opus, highSonnet, mediumSonnet, low
      EconomySonnet, highSonnet, lowHaiku, low
      QualityOpus, extra highOpus, highSonnet, medium
      You can then change any single role.
    • How many workers at once? Three is suggested.
    • Which branch? The one your PRs go into, usually main.
  3. It installs what is missing. The tracker tool, each agent tool your roles use, and the skills each worker needs to code, test, review and write a PR. If a tool needs you to log in, it gives you the exact command.
  4. It turns the loop on. It saves your answers in docs/agents/orchestrator.md, creates the four labels, starts the once-a-minute check in Orca and runs one test check. When you see "the precheck works", you are ready.

Running setup again is always safe. It keeps everything that already exists and only adds what is missing, so it is also how you change your answers later.

Your first issue

Label an issue ready-for-agent, then either say "work on N" or assign it to yourself and wait a minute. Say "status" any time to see how it is going.

9. Common questions

Does it cost anything while workers are busy?

Only the workers themselves use AI. The once-a-minute check is a plain script, and your chat goes quiet after each request. Nothing keeps polling in the background.

Can a worker merge its own PR?

No. Workers never merge and never change the labels. Only you merge, by saying "merge N" or merging on the tracker. A merge on the tracker is noticed on the next tick, which then cleans up.

Will it start work I did not ask for?

No. The tick only takes issues that are ready and assigned to you (or are children of a parent assigned to you). Saying "work on N" starts an issue directly.

Can I watch a worker?

Yes. Each worker runs in its own Orca terminal and copy of the repo, with the issue open in a tab next to it. Open it in Orca at any time.

What if two issues touch the same code?

Each worker has its own copy of the repo, so they never step on each other while they work. Any clash shows up in the PR, where you review it as usual. If one issue must go first, mark it as blocking the other, and the second waits.

Can I go back to the old version?

10. Words you will see

Orchestrator
Your main Claude Code chat. It hands out work and reports back, and never codes itself.
Worker
One AI agent working on one issue, in its own copy of the repo.
Worktree
That private copy of the repo, named after the issue, such as issue-42.
Harness
The agent tool a worker runs in: claude, codex, cursor, pi or copilot.
Role
Heavy, medium or light. It decides which tool, model and effort a worker gets.
Tick
The once-a-minute check that moves labels and starts new workers.
Slot
A place for one running worker. You choose how many there are.
Parent and child
A story and the smaller issues under it.
Resume
A fresh worker picking up a stuck issue after you answered it.
